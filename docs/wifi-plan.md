# Wi-Fi, box art and RetroAchievements

Start with one Wi-Fi-capable RG SP, its current BaseOS card, and a known GB, GBC or GBA ROM. Keep Socket usable from power-on with no credentials or access point. Ship the work in three increments. Box art and RetroAchievements can ship independently once the device has a working connection.

## 1. Connect the frontend card to home Wi-Fi

- Record the BaseOS image version. On the device, check for `wlan0`, `wpa_supplicant`, `wpa_cli`, BusyBox `udhcpc`, its lease hook, and a usable clock. BaseOS starts the radio asynchronously and handles the driver and slow-radio recovery. The frontend owns network selection, association and DHCP. On an image with an incorrect RTC, provide a bounded time-sync attempt after association and DHCP. If it fails, show a clock error and allow offline play. Use the image's DHCP hook to install the address, route and DNS. [BaseOS networking](https://github.com/pvaibhav/BaseOS/blob/687cd07eaf828ab2b4fbf1d78b2d2c4cff025e58/docs/05-runtime-power-network.md)
- Accept Slot-plus's `Config/wifi.txt` on the frontend card, with `ssid = ...` and `psk = ...`. Target one WPA2-Personal network with DHCP first. Ship an example under a different filename so an upgrade preserves the user's file. Parse the file as data, handle spaces and punctuation, and create the supplicant config in private RAM files. The removable card contains the user's credentials. [Slot-plus network script](https://github.com/nickclyde/slot-plus/blob/e2aefa04ba327e8e7d25d62b0cdd9084866438d0/card/System/slotnet.sh)
- Start one optional background worker from `card/System/launch_frontend.sh`. Give it bounded interface and association waits, DHCP renewal, and retry with backoff. Detect an existing usable connection. Keep the worker alive while Godot yields to RetroArch. On wake, recheck the lease and reconnect if needed. On exit or power-off, stop only the processes Socket started before the existing bounded `8821cs` unload. Put shutdown coordination in the shared `poweroff.sh` path so it also runs when the hardware helper initiates shutdown. [Slot-plus reconnect logic](https://github.com/nickclyde/slot-plus/blob/e2aefa04ba327e8e7d25d62b0cdd9084866438d0/crates/slot-cheevos/src/wifi.rs)
- Update `FrontendBridge.get_network_status()`. It currently sets both Wi-Fi and internet from `wlan0/operstate`. Derive link state from association and IP configuration. Use the actual service request to determine reachability. A DNS failure, captive portal, TLS error or unavailable artwork server must still leave the library and game launcher usable.
- Extend `tests/test_resident_launcher.py` with fake network commands. Cover CRLF files, literal quotes, # and = in credentials, valid passphrases and 64-digit hex keys. Check a late interface, a failed join, repeated starts, and shutdown with an active retry.
- **Device check.** Cold boot with no config, with a bad password, and with a working network. The first two boots must reach the library and launch a game without waiting for network timeouts. On the third, verify a lease, DNS and a certificate-validated HTTPS request. Cycle the access point, close and reopen the lid during an active request, and power off during a retry. Retain an existing lease across shallow lid sleep, suppress active retries while asleep, and measure the change in drain. Check for duplicate clients and shutdown delays.

## 2. Enable Socket's existing artwork downloader

- In `tools/patch-socket.py`, keep the Linux scan's early library save and local cache attachment. Make its unconditional return conditional. Reuse the APK's GamesDB scraper for missing metadata or artwork after a connected scan. Keep the existing API credential inside the user-built pack. Keep the desktop setup and offline scan working. Check the endpoint and credential scope for each supported APK. Socket 0.10.1 uses `socket.depmots.com/v2/match`. The host tool uses `gamedb.depmots.com/v1/match`. Test that each can read the other's artwork cache.
- Cover every scrape entry point in each supported APK. In 0.10.1, Scan All calls `_run_scrape` directly, and a single-game rescrape deletes existing cache files before it makes the request. Stage and validate replacements before updating paths or replacing cached files. Preserve curated art, favorites and existing metadata on a normal scan. Refresh the visible cartridge after a successful download. Reuse the existing cancellation flow. Bound request time, retry and image size, and send the GamesDB credential only to its own HTTPS endpoint.
- Check for unrelated network activity during boot and launch. In 0.10.1, guard silent emulator-list updates so they cannot overwrite the installed core list. Keep RomM save transfers and ROM downloads outside this rollout. Verify that an existing profile cannot unexpectedly pull remote saves or stall a launch once Wi-Fi connects. Feedback and missing-art reports must require an explicit user action.
- **Acceptance.** From the controller, scan a library containing one curated game and one uncached game with a known match. The new art must appear without a restart and remain after a reboot with Wi-Fi off. Repeat with no match, rate limiting, cancellation and a connection drop during an image transfer. Confirm that the previous artwork and library data survive. Extend the packed-app tests for 0.3.2, 0.8.0 and 0.10.1 with deterministic responses for both connected and offline paths.

## 3. Enable RetroAchievements in gameplay and in Socket

- Let the bundled RetroArch 1.22.2 own game identification, runtime memory checks and unlock submission. The local build enables networking, SSL and cheevos. Add a build assertion for those features. First fix or replace the selected mbedTLS transport's optional certificate verification and test that it rejects an untrusted certificate and a wrong hostname. Verify a successful connection with the target clock and CA roots before entering real credentials. [Pinned RetroArch TLS implementation](https://github.com/libretro/RetroArch/blob/v1.22.2/libretro-common/net/net_socket_ssl_mbed.c)
- Use Slot-plus's card-based account setup. Read `Config/retroachievements.txt` with a username and initial password. After a verified login, atomically replace the password with the returned gameplay token. Persist this small credential record directly at successful login. The existing `config_save_on_exit = "false"` and RAM session config would otherwise lose the token. Handle expired tokens with a clear sign-in message. Keep secrets out of command arguments, game logs and generated distributions. [Slot-plus account setup](https://github.com/nickclyde/slot-plus/blob/e2aefa04ba327e8e7d25d62b0cdd9084866438d0/site/retroachievements.html)
- Feed achievements settings through `card/System/socket/launch_game.sh` for normal launch and cold resume. Use softcore to preserve rewind, save states and MENU-hold resume. Apply the account settings after per-platform overrides. Set `cheevos_enable = "true"` only for an opted-in account and explicitly set `cheevos_hardcore_mode_enable = "false"`. Keep emulator startup independent of login success. If cold resume beats DHCP, resume immediately and show that achievements are unavailable for this session. Test the next online launch. Verify that a notification is visible with this port's menu and assets. Start with mGBA, which RetroAchievements lists for all three handheld systems. Treat gpSP as unverified. Treat retry after a connection loss as limited to the current RetroArch session. [Libretro achievement behavior](https://docs.libretro.com/guides/retroachievements/) and [supported cores](https://docs.retroachievements.org/general/emulator-support-and-issues.html#game-boy-advance)
- Reuse Socket's achievement panel on APK versions that provide it. Its username and Web API key serve progress and badge queries. Keep that key separate from the gameplay token. In 0.10.1 the Linux hash function returns an empty result for normal GB and GBC ROMs. Route supported handheld ROMs through the existing bridge with the real ROM path, including subfolders. Keep Web API keys out of logged URLs. Allow failed hash-list downloads to retry in the resident frontend. Verify identification and refreshed progress for GB, GBC and GBA, including a first lookup after offline boot.
- **Acceptance.** On an RG SP, sign in, launch a recognized ROM, earn one softcore achievement and confirm it on the account. Quit, reboot, launch again using the saved token, and check the frontend's refreshed count. Exercise rewind, lid sleep, MENU-hold power-off and cold resume. Repeat with an unknown ROM, expired credentials and unavailable Wi-Fi. Each game must still launch. Inspect logs and the card for unintended credential copies.

Extend the launch and resume tests with synthetic credentials to check option precedence, token persistence and redaction.

After device verification, update the offline-only statement in `README.md`, add card setup and failure diagnosis, and record the tested BaseOS image, Socket version and core in the compatibility docs. The initial scope is outbound Wi-Fi, Socket artwork and softcore achievements. Static addressing, a controller Wi-Fi keyboard and replay of offline unlocks across power cycles can be considered separately.
