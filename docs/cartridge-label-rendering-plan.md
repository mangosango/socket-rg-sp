# Plan: native-resolution cartridge labels

This is the original prototype plan. The current implementation draws only the selected label at native pixel density; see [rendering behavior, measurements and handheld benchmark](rendering.md#experimental-native-cartridge-labels).

**Recommendation:** prototype a 0.60× casing with a 1.00× label on the RG SP, behind an off-by-default switch. Keep the label as a lit 3D surface, not a flat image over the UI. Start with the 0.10.1 main carousel and an opaque GBA cartridge. Do not change the saved scale or the shipping default to run the experiment.

## What the split buys

Today `tools/patch-socket.py` patches Socket's `scenes/render_scale_3d.gd` to size a single 3D `SubViewport`. Its `TextureRect` displays the result through `overlay/shaders/display_aa.gdshader`. By that point the casing and artwork are already one image: increasing the artwork texture size or sharpening the final image cannot recover detail lost in the 3D render.

For a carousel covering the 720×480 panel, 0.60× is **432×288**. That is 36% of native pixels for the casing pass, versus 56% at the current 0.75× default (540×360). This is a pixel budget, not a frame-rate prediction. The label still needs its full material, and another GLES target, shadows, clears, resolves and compositing can consume the saving.

## Implementation sequence

1. **Establish three single-pass controls.** Use the packed project, the same artwork, camera pose, lights and casing at 1.00× (visual reference), 0.75× (shipping default) and 0.60× (cost floor for the prototype). Capture the *displayed* 720×480 frame, not just the 3D texture. Include fine lettering and diagonal lines: a large solid-color sticker can pass color tests even when unreadable.
2. **Split one known model.** At the render-scale patch point, retain the scaled body viewport and add one transparent native label `SubViewport` for the carousel, not one per cartridge. Derive native size from the displayed container in physical pixels, before applying the body slider and cap; do not use the 1920×1280 UI layout as the target. Share the `World3D`; match the active camera's transform, projection, aspect and offsets in the same frame. Use camera layers to draw body and label separately. Identify the actual mesh **and surface** used by the cartridge's cover-material setter. Layers select instances, not surfaces: if they share a mesh, isolate just the label surface or mark that model unsupported. Do not duplicate the game/cartridge logic or identify all labels by one sticker shader filename.
3. **Keep the original material and composition.** The native draw must use the active cover material, UVs, artwork, crop/zoom and animated foil/reveal parameters, including material replacements during customization. Match lights, shadows and tonemapping to the reference. Feed the native texture into the existing display pass: upscale/filter the casing first, then composite the native premultiplied label over it (`label + body * (1 - label.a)`), then apply UI modulation once. Do not run the silhouette filter over sticker text. Bypass the split entirely when both physical targets are the same size.
4. **Make visibility a go/no-go test.** Independent viewports do **not** share depth. A native label drawn last could show through the back of its own case or through a nearer cartridge. For opaque cartridges, prototype a native depth-only draw of the occluding casing geometry from **all** visible carts before the label draw; it must write depth without filling the transparent color target or shading a second full casing. Verify that ordering and target behavior on Compatibility/GLES, including MSAA. If that cannot be done cheaply and correctly, stop the prototype rather than shipping an always-on-top sticker. Clear/frosted casings read the scene behind them for refraction; depth alone does not preserve that. Keep the **whole carousel frame** on the existing single-pass path when any visible model or finish is unsupported, including during transitions. Only enable glass or disc variants after their own comparisons pass.
5. **Integrate only after the spike passes.** Keep the existing slider as body scale in split mode; retain its current meaning in fallback. Switch atomically when carts enter/leave, styles change or the view resizes: never show a stale or double label. Mirror the body's update-once, pause, resume and hidden states; release the native target on teardown. Check the existing MSAA preference and session fallback, and ensure `shader_startup.gd` warms the variants that actually draw. Implement in tracked patches/overlay code, not generated `work/` scenes. Leave 0.8.0 and 0.3.2 unchanged until their surface layouts and pack tests are verified.

## Evidence required to ship

| Question | Check |
| --- | --- |
| Is the label actually sharper? | Extend `tests/app/test_carousel_labels_render.gd` with a fine-detail fixture. At identical front and tilted poses compare the label interior of the **final composite** to the native reference. Require lower error than both reduced single-pass controls, readable small type on the panel, and unchanged foil response, highlight detail and UI outside the carousel. |
| Does it stay attached? | Capture a short idle tilt and a three-cart scroll, including overlap, back-facing labels, cutout edges and a mid-scroll material change. Reject bleed-through, halos, doubled edges or one-frame drift. Exercise resize, empty library, pause/resume, linear/edge filters and MSAA on/off. Use `tests/app/test_glass_label_render.gd` to verify that unsupported glass still matches the single-pass control. |
| Is it worth the second pass? | Add the split case to `tests/app/bench_render.gd` / `bench_device.sh`. Interleave warmed single-pass controls and split runs on the **same RG SP**, at fixed brightness, FPS cap, MSAA state, fixture and input sequence. Record median frame time, navigation p95, draws, actual target sizes and fallback state. Time both viewports and the final window, not just the body. Check cold startup separately. |

**Decision:** retain the single-pass default unless split 0.60×/1.00× beats single-pass 0.75× on handheld frame time beyond run-to-run variation, does not regress navigation p95, and wins the label comparison without visibility defects. A win only against native 1.00× is not enough to replace today's default. If the second pass costs too much, keep the measurements and stop; do not add an engine fork or another user-facing slider as part of this trial.
