# Socket launcher improvements

The current release uses **MENU** to toggle Device Settings in the launcher and
during play. The original plan below records the earlier shortcut. See
[Controls](controls.md) and [RetroArch](retroarch.md) for the current menus.

Target the RG SP at its native 720×480 resolution. Start with Socket 0.10.1 and check 0.8.0 and 0.3.2 before release. Deliver the work in three changes. Capture the current build first so each change has a comparison point.

## 1. Make cartridges sharper and navigation faster

Socket keeps a 1920×1280 logical layout. On the RG SP the port caps cartridge rendering at 480×320, disables 3D MSAA, then applies a five-to-nine-read edge filter. The filter can soften fine label detail. The mounted card's frame log showed a median of 26.9 rendered FPS across 72 main-menu samples at 480×320. The log does not distinguish scrolling from idle. Rendering at 720×480 would shade 2.25 times as many pixels, so first measure which passes can pay for the extra detail. [Rendering notes](rendering.md) · [Version-specific viewport patches](../tools/patch-socket.py) · [Display filter](../overlay/shaders/display_aa.gdshader)

1. Record three identical runs on the same device, library and theme. Use a cartridge with fine label text and another with a dark, curved silhouette. Capture native-size images at rest, while scrolling and in inspect mode. Use the existing frame log for rendered FPS, worst frame, draw calls and viewport size. Add a benchmark-only frame-time sample for the 95th percentile during navigation. Record cold and cached time to first usable input separately.
2. Use one deliberately tiny 3D target to estimate how much frame time depends on pixel count. Then compare 480×320, 600×400 and 720×480. At each size, compare the current filter with a plain linear pass that preserves premultiplied alpha. Try 2× MSAA only if silhouettes still need it. Measure one change at a time. Profile the shadow and glass passes and redundant draws behind fully opaque screens. Keep the visible carousel motion, transparent edges, foil highlights and shadow detail. Apply the selected cap to both the modern display texture and the 0.3.2 container path. Verify the effective target at the low and high ends of Socket’s existing render-scale setting.
3. Trace a small menu label from the active font through the UI viewport to panel pixels. Compare the actual glyph raster size, antialiasing, hinting, texture filtering and fractional placement. Fix the first stage that loses detail. Keep the theme typefaces, logical layout and deliberate pixel-font styling. Check the library, settings, focus outlines, controller dialogs and native-pixel HUD at supported UI scales. The 3D filter cannot correct these glyphs. [Controller dialog sizing](../overlay/addons/FrontendPlugin/controller_dialog.gd)
4. Select a default only when native-size images show cleaner silhouettes and readable label detail in motion, small UI text has smoother strokes, and repeated navigation has a lower 95th-percentile frame time beyond baseline variation. Also log the first appearance of foil labels and frosted glass after warmup. A rare multi-second stall can disappear in a percentile or FPS average. If higher resolution misses that target, optimize the measured bottleneck and repeat the comparison. Extend the existing real-renderer image checks for diagonal edges, alpha halos and cartridge labels. [Edge tests](../tests/app/test_display_aa_render.gd) · [Carousel label tests](../tests/app/test_carousel_labels_render.gd)

## 2. Open Device Settings with Select + Menu

Place a controller-first panel over the current launcher screen. Use the active Socket theme, typefaces, spacing, selection highlight and button prompts. Up and Down select a row, Left and Right adjust a level, A opens or confirms, and B returns to the previous focus. Keep the selected cartridge and scroll position. The proposed first release handles this shortcut while Socket owns the display.

| Row | Behavior |
| --- | --- |
| Brightness | Show levels 1 through 10. Apply each step immediately through the hardware helper and display its confirmed value. |
| Volume | Show 0 through 100 in steps of 5. Use the existing gain curve and mute at zero. Reflect physical volume-button changes while the panel is open. |
| Wi-Fi | Turn Wi-Fi on, select a nearby network or enter a hidden network name, enter its password, and connect. Show connection state and provide Retry and Forget. Switching Wi-Fi off keeps the saved network. |
| Bluetooth | Turn the adapter on, find a nearby accessory, pair and connect. Show paired accessories with actions to connect, disconnect or forget. Show an unavailable state when the adapter or required services are missing. |

- Handle the chord where physical Select and Menu can be consumed before either triggers its usual action. While the launcher is active, briefly defer a standalone Menu press as well as Select, which already has a 250 ms delay. Bypass the new chord when a game owns input. Publish one numbered open request in the session run directory and consume it once in Godot. Check both press orders and release orders, holds, repeats and wake with a button down. One chord must open one panel. Preserve Select + D-pad and RetroArch's Menu tap and hold. During shader startup, discard the chord so a panel cannot appear after boot. [Input state machine](../engine/fbdev/hardware_input.h) · [Control behavior](controls.md)
- Add a small request channel in the session run directory for Godot to send validated level changes to `socket-hardware`. Use atomic replacement and acknowledge the applied request. Translate the snapshot’s 0–9 brightness index to 1–10 in the panel. Preserve the existing snapshot and saved-file formats. Keep it responsible for calibration, clamping, persistence and publishing the current values. Reuse its snapshot so the panel, shortcuts and RetroArch agree after a game or a reboot. [Hardware helper](../engine/fbdev/hardware.c) · [HUD reader](../overlay/addons/FrontendPlugin/controls_hud.gd)
- Run radio operations outside the UI thread. Give each scan, join and pairing attempt a timeout and a Cancel action. Stop discovery and dismiss pending prompts on exit or sleep. Ignore late results from a canceled attempt. Keep radio preferences separate from shutdown markers. Verify the input chord, focus and cancellation in packed controller tests across all three Socket versions.

### Join a Wi-Fi network on the handheld

1. Extend the existing Wi-Fi worker to scan on request, including on a fresh card with no credentials. Show network names and security types. Offer **Enter network name** for hidden SSIDs. Start with the port’s existing WPA2-Personal and DHCP support. Mark unsupported security types in the list. Use Socket’s controller keyboard for the SSID and masked password, including its preview. Supply a themed controller keyboard on any supported pack that lacks it. **Join** submits the credentials. Back discards the edit. [Wi-Fi worker](../card/System/socket/wifi.sh) · [Launcher supervisor](../card/System/launch_frontend.sh)
2. Keep one saved network compatible with `Config/wifi.txt`. Validate the SSID and passphrase against the existing parser, including spaces, punctuation and raw 64-digit hex keys. Report input that cannot round-trip through the card format before joining. Stage candidate credentials in private RAM and keep secrets out of command arguments and logs. Confirm association and a DHCP lease for the selected network before atomically replacing the saved profile. On cancellation, failure or a card-write error, preserve the prior profile and offer to reconnect. Show authentication, DHCP and save errors separately. Confirm **Forget** before removing the saved profile and disconnecting. [Credential parser](../engine/wifi-config.c) · [Card format](../card/Config/wifi.txt.example)
3. **Device acceptance.** Start with an empty profile and join a visible network using only the controller. Repeat with a hidden SSID and a password containing spaces and punctuation. Reboot and verify automatic reconnection. Try switching networks with a wrong password, cancel a pending join, and verify that the previous network still works. Forget it and verify that it stays forgotten after reboot. Extend the worker tests with simulated scans, delayed results and failed saves. [Wi-Fi tests](../tests/test_wifi.py)

### Pair a Bluetooth accessory on the handheld

1. Use the BaseOS controller attach and BlueZ services. Verify the adapter and pairing tool on the target image. **Add accessory** starts bounded discovery. List nearby devices by name and show an address suffix to distinguish duplicate names. Selecting a device starts pairing for that device only.
2. Keep a BlueZ pairing agent active for the transaction. Present the prompt requested by the accessory, including numeric comparison with Accept and Reject, PIN or passkey entry, and instructions for a code shown on the handheld. For accessories with no code, use the user's device selection and explicit **Pair** confirmation. Cancel or reject unexpected requests. Report **Paired** when BlueZ confirms the bond and **Connected** when it confirms the connection. If the connection fails after pairing, offer **Connect** without repeating pairing. Use the existing BlueZ bond store for reconnection across reboots. Confirm **Forget** before removing the bond.
3. **Device acceptance.** Pair a headset from an empty paired list using only the RG SP controls. Verify the intended audio route with audible playback, disconnect and reconnect it, then reboot and reconnect from the paired list. Exercise a code prompt with a compatible accessory, reject a mismatched code, cancel discovery, and retry after an accessory disappears. Forget a bond and verify that a new pairing is required. Test sleep, wake and power-off with Bluetooth active and Wi-Fi connected. Use simulated BlueZ events for rejection, timeout and late replies, then verify the controller flow on the actual image.

## 3. Animate the shader warmup screen

Keep the exact **Compiling shaders** label. Show a rotating indicator against the same moving dot pattern and palette as Socket's launch screen. Reuse the installed pack's scrolling-dots material and spinner where present. Check each supported pack for those resources and use a small drawn arc for versions without the spinner. Reuse presentation assets without starting the boot scene or loading the library a second time. [Startup overlay](../overlay/addons/FrontendPlugin/shader_startup.gd)

- Present the overlay before the first warmup draw. Keep its animation processing while navigation is paused. Animate on the existing front and back warmup frames. Each variant already waits for two draws. Keep the live carousel render target and avoid extra waits for the spinner. Match the apparent dot spacing across the transition from the logical boot layout to the native-pixel overlay. Preserve shader-cache reuse and the current cleanup of pause, input, font scaling and viewport state.
- Capture one cold start on a disposable test cache and repeated starts on the same cache. Verify that the dots and spinner move during warmup, the text stays legible in light and dark themes, and there is no blank flash before the library accepts input. Require cached time to first input to stay within the repeat-run baseline variation. Record cold-start overhead and repeat with an empty library. A synchronous GLES compile can stall presentation even when the animation code runs. Record the longest visible freeze and use that measurement to decide whether further scheduling work is needed.
- Extend the packed startup checks for all three versions and use a graphical run to compare successive frames. Headless tests cover boot gating and cleanup. The RG SP verifies animation, compile stalls and cold versus cached timing. [Startup tests](../tests/app/test_shader_startup.gd)

Use pack snapshots for compatibility checks if older APKs remain unavailable. Record which versions had a fresh APK-to-pack build. Capture the rendering and boot baselines first. Device Settings can then proceed independently while the rendering candidates are measured. Run final startup timing with the selected renderer, since the warmup must exercise the settings that ship.
